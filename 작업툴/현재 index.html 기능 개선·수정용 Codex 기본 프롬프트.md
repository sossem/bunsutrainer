# 3. 수정 범위 제한

이번 작업에서 가장 중요한 원칙이다.

**내가 아래의 `[수정 요청]`에 명시한 사항을 중심으로 수정한다.**

- 요청하지 않은 기능 삭제
- 불필요한 대규모 리팩터링
- 전체 HTML 재작성

- 기존 기능을 새로운 방식으로 전면 교체
- 필요 없는 라이브러리 추가
- 프레임워크 임의 도입

더 좋은 방법이 있다고 생각해도 이번 요청과 관계없는 부분은 건드리지 않는다.

4. 다른 기능에 영향을 주지 않는다.

단순히 코드 스타일을 예쁘게 만들기 위한 리팩터링은 하지 않는다.

# 9. localStorage 및 기존 데이터 호환성

매우 중요하다.

현재 사용자에게 저장되어 있는 데이터가 새로운 수정 때문에 사라져서는 안 된다.

다음을 금지한다.

- 기존 localStorage 전체 초기화
- 저장 키 임의 변경
- 기존 데이터 삭제
- 기존 데이터와 호환되지 않는 구조로 일방적 변경

데이터 구조 확장이 필요하다면 기존 데이터에서도 정상 작동하도록 기본값 또는 migration 처리를 한다.

예:

기존 객체에 새로운 값이 없다면

```javascript
const timerEnabled = data.timerEnabled ?? false;
```

와 같은 방식으로 이전 데이터와 호환되도록 한다.

# 10. 이벤트 중복 방지

기능을 추가하면서 이벤트 리스너가 중복 등록되지 않도록 확인한다.

특히 다음 문제를 점검한다.

- 버튼 한 번 클릭했는데 함수가 두 번 실행
- 문제 두 번 생성
- 점수가 두 번 증가
- 타이머가 여러 개 동시에 실행
- Enter 입력이 중복 처리
- 다음 문제 두 번 이동
- localStorage 중복 저장

필요하다면 기존 이벤트 구조를 먼저 파악한 후 추가한다.
