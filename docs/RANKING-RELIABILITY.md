# 랭킹 반영 신뢰성 수정 · 2026-10-21

## 확인한 범위와 재현 증거

작업 시작 시 `git status --short`, `git diff --stat`는 비어 있었다. index.html의 모듈 로딩, app의 완료/이동/로그인 흐름, competition/provider/화면 구독, session-extras의 점수·상태 처리, 영역별 저장 adapter, 저장 검증, 점수 상한, 규칙 및 기존 테스트를 분석했다.

사용자가 제공한 배포 규칙은 로컬 `firestore.rules`와 같은 조건이다. 관리자 API로 실제 배포본을 다운로드한 것은 아니다. `https://sossem.github.io/bunsutrainer/`의 index.html 및 app/competition/session-extras/platform/trainer-adapters 파일은 수정 전 HEAD와 줄바꿈을 제외하고 같았다. 따라서 조회 시점의 배포 파일 누락은 확인되지 않았다. 개별 사용자의 브라우저 캐시 상태는 확인하지 못했다.

운영 Firestore에서는 이번 주(20261019) 분수·소수 학급 컬렉션에 각 최대 5건 제한으로 점수 카운터와 버전 필드만 읽었다. 각 영역에서 조회된 학급 문서 1건씩에는 누락 카운터나 비정수 카운터가 없었다. 학생 문서·PIN 검증값은 읽지 않았고, 운영 쓰기는 수행하지 않았다. 이 표본으로 다른 문서의 상태까지 보장하지 않는다.

수정 전에 실패를 확인한 테스트:

- 서버 연결을 기다리는 동안 로그아웃했는데도 이전 제출이 provider로 전달됐다. `Account changes while connecting...` 테스트가 실패했다.
- 반영 결과 미확정 응답을 저장 계층이 무조건 `failed`로 바꿨다. `Unconfirmed contribution...` 테스트가 실패했다.
- 기존 `Lost contribution response...` 테스트는 서버 저장 성공 후 응답을 지연시켜 앱이 실패를 반환하고 재시도를 요구하는 현상을 이미 재현하고 있었다. 수정 후에는 서버 영수증으로 성공을 확인한다.
- 소수의 비대상 유형이 포함된 회차는 `prepare()`가 competition/rankingEnabled를 끄는데, 기존 결과/기록 화면은 rankingEnabled가 false이면 이유를 표시하지 않았다. 중간 종료 또한 기존 정책상 합산하지 않는다. 정책은 변경하지 않고 이유만 표시한다.

이 조건들은 재현된 결함/안내 누락이며, 사용자가 겪은 특정 운영 회차의 원인으로 확정한 것은 아니다. 해당 회차의 기록 상태와 유형·점수는 제공되지 않았다.

## 수정한 파일과 방식

- `js/competition.js`
  - 기존 8초 제한은 그대로 유지한다. 제한 초과를 구분하는 코드를 부여한다.
  - 초과 시 해당 영역·주간·회차의 영수증을 서버에서 한 번 조회한다. 서버 조회도 기존 제한 시간으로 종료한다. 캐시 문서로 성공을 판정하지 않는다.
  - 영수증의 영역·회차·학생·학급·주간·점수·문제 수·첫 정답 수가 일치해야 성공으로 복구한다.
  - 확인되지 않으면 pending과 원래 요청의 완료 Promise를 반환한다. Promise는 저장하지 않는다.
  - 같은 영역/주간/학생/회차의 진행 중 요청을 공유해 재시도로 병렬 트랜잭션이 늘어나지 않게 한다. 추가 자동 쓰기 재시도는 도입하지 않았다.
  - 로그인 객체와 PIN을 제출 시작 시점에 고정하고, 연결 후/계정 확인 후/트랜잭션 시작과 쓰기 준비 전 계정·주간을 다시 검사한다. 이미 서버로 보낸 커밋을 취소할 수 있다고 가정하지 않는다.
  - 권한 거부와 연결·동시성 오류 안내를 구분한다.
- `js/session-extras.js`
  - 미확정은 pending으로 유지하고 늦게 도착한 서버 응답으로 기록 상태를 갱신한다.
  - 학습 영역과 회차를 함께 사용해 중복 조작을 막는다. 다른 영역으로 이동해도 원래 영역의 저장소를 갱신한다.
  - 오래된 실패 응답이 이미 확인된 성공을 덮어쓰지 않게 한다. 사용자가 삭제한 기록을 복구하지 않는다.
  - 실패/미확정 안내를 학습 기록에서 다시 볼 수 있게 하고, 비대상 유형·중간 종료·복습 등의 제외 이유를 표시한다.
- `js/storage.js`
  - 선택 필드 `classContributionMessage`를 길이 제한과 함께 보존한다. 기존 기록에는 필드를 강제로 추가하지 않는다.
- 관련 Node 테스트 3개 파일과 실제 에뮬레이터 테스트를 확장했다.

## 기존 기능과 데이터 영향

분수/소수 계산·문제 생성·정답 판정·점수 계산·학습 대상 정책은 그대로다. 타이머·전체화면·단축키·디자인·학년 선택·주간 경계도 변경하지 않았다. 경험치·배지 데이터는 건드리지 않았다.

localStorage 키, 저장 버전, 온라인 컬렉션 이름과 영수증 ID는 그대로다. 기존 기록 및 서버 점수를 삭제·이동·초기화하지 않는다. 새 안내 문자열만 선택 필드로 추가한다. 학급/개인/영수증의 원자적 트랜잭션과 회차 중복 방지는 유지한다.

`firestore.rules`는 변경하지 않았다. 에뮬레이터에서 정상 카운터를 가진 scoreVersion 2 문서와 trainerId 없는 문서, PIN이 있는 미연결 소수 계정의 반영을 검증했다. 누적 필드가 없는 손상 문서는 거부됨을 확인했고, 이를 지원되는 구형 데이터라고 추정하여 임의 보정하지 않았다.

## 운영 적용과 남은 확인

이번 작업은 로컬 수정과 검증까지 수행했으며 커밋·푸시·배포는 하지 않았다. Firebase 규칙 재게시도 필요 없다.

1. 변경된 세 JavaScript 파일을 기존 GitHub Pages 배포 방식으로 반영한다.
2. 배포 완료 후 강력 새로고침한다. 사이트 데이터/localStorage는 지우지 않는다.
3. 같은 주간·같은 계정으로 기록의 `반영 다시 시도`를 실행한다. 이미 반영된 회차는 영수증으로 중복을 막는다.
4. 문제가 남으면 기록의 상태와 지속 표시되는 안내, 학습 영역·유형·점수로 실패 단계를 구분한다. PIN이나 개인 식별정보는 공유할 필요 없다.

운영 사용자의 특정 회차·브라우저 캐시·실제 네트워크 실패 조건과 배포 후 성공 여부는 미확인이다. 따라서 운영 복구 완료로 보고하지 않는다. 온라인 반영 여부를 판단할 수 없는 상태는 성공으로 표시하지 않는다.
