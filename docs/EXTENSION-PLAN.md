# 분수트레이너 랭킹·타이머 확장 기록

## 2026-09-14 변경 사항

현재 개인 학습은 **전국학급랭킹전**으로 제공한다. 나의 성장 화면과 경험치·레벨·배지 지급을 제거하고 `gamification.js`의 난이도·첫 시도·연속 정답 점수 계산만 학습에 연결한다. 타이머는 선생님과 함께 수업에서 유지하고 개인 학습의 타이머와 학습 도구 설정은 제거했다. 기존 성장·학습 기록의 저장 키와 데이터는 보존한다.

학교·학년·반과 최대 10회 주사위 후보에서 확정한 닉네임으로 입장한다. `competition.js`는 같은 반·같은 주 닉네임 등록, 학급/개인 동시 점수 반영, 세션 영수증 중복 방지, 월요일 오전 8시(한국 시간) 주간 전환과 실시간 구독을 담당한다. 지난주 컬렉션은 삭제하거나 0으로 덮어쓰지 않고 보존해 이번 주 결과와 함께 표시한다. UI는 `competition-ui.js`·`competition.css`로 연결하고 이전 랭킹 조회 화면은 유지한다. 별도 서버의 예약 초기화 작업은 사용하지 않는다.

새 localStorage 키는 `bunsu.competition.identity.v1`, `bunsu.competition.drafts.v1`이며, 기존 학습 기록에는 선택 필드 `competition`만 확장한다. 상세 현행 구조는 [IMPLEMENTATION.md](IMPLEMENTATION.md), 실행 방법은 [README](../README.md), 최신 실행 증거와 운영 검증 한계는 [TEST-RESULTS.md](TEST-RESULTS.md)를 확인한다.

**이하 내용은 2026-09-13 이전 버전의 설계·검증 기록이다.** 개인 타이머·성장 보상·데모 참여 등의 표현은 현재 기능 안내가 아니다.

## 2026-09-13 구현 상태 (이전 버전 기록)

아래는 중단 전의 설계 기록이다. 재개 점검에서 세 모듈의 앱 연결이 빠져 있음을 확인했고 `index.html`, `app.js`, `session-extras.js`, `ranking-ui.js`, 확장 CSS를 통해 연결했다. 기존 계산·출제·학습·전자칠판 화면은 유지했다. 모듈 테스트와 실제 브라우저의 기본 기능·타이머·성취·데모 랭킹·학교 선택 검증 결과는 [TEST-RESULTS.md](TEST-RESULTS.md)에 기록한다. 온라인 운영 쓰기와 보안 규칙 변경은 수행하지 않았다.

## 수정 전 상태

`redesign`의 미커밋 완성본을 기준으로 확장한다. `index.html`은 로컬 스크립트를 defer로 로드하고, 5단원·28유형 출제는 `problem-generator.js`, 수학과 판정은 `fraction.js`, 표현은 `ui.js`, 상태·화면·이벤트 위임은 `app.js`에 있다. 개인 학습의 첫 제출/재도전·힌트·풀이·오답 재학습과 전자칠판의 단계 공개·단축키·전체화면이 연결되어 있다.

현재 성적은 첫 제출 정답 수/정답률이며 게임 점수는 없다. 학습 기록은 `bunsu.learning.v1`의 `{version:1,records:[...]}`에 저장된다. 현재 기록 필드와 오답 문제 데이터를 유지해야 한다.

Git HEAD의 과거 단일 `index.html`에는 실제 Firebase 프로젝트 `bunsutrainer`, Firestore `classRankings_YYYYMMDD`, 한국 시간 월요일 기준 주차, 학교 JSON 검색, 우리 반 강조, 이번 주/지난 주 상위 10개 학급이 있다. 게임 요소는 정답 500점 + 최대 500점 시간 보너스와 큰 점수 애니메이션, 오답 3초 대기였다. 경험치·레벨·배지는 없었다. 타이머는 문제별 10·20·30초 및 사용자 설정, 랭킹전 20초 고정이었다. 오답 시 기존 타이머를 즉시 취소하지 않는 중복 전환 위험이 있었다.

## 재사용과 통합

1. Firebase 프로젝트 설정·학교 JSON·한국 시간 주차·학급 집계·우리 반 강조를 재사용하되 `ranking.js` 공급 계층으로 옮긴다. 새로운 점수는 `classGrowthRankings_YYYYMMDD`, 예전 점수는 기존 컬렉션 읽기 전용 화면으로 구분한다. 명시적 체험 모드는 별도 localStorage로 운영하고 온라인 결과와 섞지 않는다.
2. 점수 피드백의 의도를 작은 성취 표시로 유지한다. `gamification.js` 한 곳에서 정답·난이도·콤보·힌트/시간 보너스, 경험치, 레벨, 배지와 학급 기여를 계산한다. 벌점과 자동 문제 전환은 도입하지 않는다.
3. `timer.js`의 단일 시계 구현을 두 모드에서 사용한다. 기본은 0초(사용 안 함), 10/20/30/60초와 1~3600초 직접 설정. 실제 시간 경과로 계산하며 화면 렌더링과 분리한다. 문제 전환과 종료 때 이전 타이머를 정리한다.
4. 전자칠판 타이머는 기존 상단 행에 배치하고 문제 영역 크기·분수 크기·4행 레이아웃을 유지한다. T로 시작/일시정지, R로 초기화한다. 시간 종료는 0에서 멈추고 선택적으로 정답만 공개한다.
5. 개인 기록의 기존 key/version/필드를 유지하고 추가 필드는 선택적으로 저장한다. 성취·학급 선택·체험 랭킹은 별도 키를 쓴다. 이전 기록을 읽는 것만으로 보상을 새로 만들지 않는다.
6. 새 메뉴는 기존 헤더에 추가하고 수업 중 랭킹·개인 경험치를 노출하지 않는다. 별도 확장 CSS를 적용해 기존 스타일 파일 변경을 최소화한다.

## 검증과 변경 비교

수정 전 계산·출제 89개 테스트 통과. 현재 파일은 `tests/artifacts/extension-baseline/`에 복사했다. 기존 완료 작업이 아직 미커밋/미추적 상태이므로 Git HEAD diff와 함께 이 기준 사본을 비교해 이번 확장 범위를 판별한다.

기존 회귀 테스트를 유지하고, 가짜 시계를 사용하는 타이머 테스트, 점수/보상 중복 방지, 저장 이전 버전 호환, 주차·랭킹 정렬·우리 반·체험/온라인 분리, 공급자 실패 테스트를 추가한다. 실제 Chrome에서 타이머 끈 학습과 켠 학습, FHD 문제 크기 불변·넘침, 시간 초과·전환·일시정지·단축키, 결과·기록·랭킹 흐름을 확인한다. 운영 랭킹에 개발용 점수를 전송하지 않고 온라인 쓰기는 모의 공급자로 검증한다.

Firestore 트랜잭션은 읽기를 쓰기보다 먼저 하고, 중복 방지용 세션 영수증과 집계를 함께 기록한다. 실제 온라인 접근은 현재 프로젝트 규칙에 의해 결정되며 임의로 보안 규칙을 변경하지 않는다. [Firebase 트랜잭션 문서](https://firebase.google.com/docs/firestore/manage-data/transactions), [보안 규칙 문서](https://firebase.google.com/docs/firestore/security/get-started).
