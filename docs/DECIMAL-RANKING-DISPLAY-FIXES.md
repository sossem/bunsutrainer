# 소수 랭킹·표시 수정 결과

## 분석과 수정 범위

`index.html`은 CSS와 전역 모듈을 순서대로 로드하며 `app.js`가 메모리 상태와 위임 이벤트로 화면을 전환한다. 분수 계산/출제/표시는 `fraction.js`, `problem-generator.js`, `ui.js`, 소수는 `decimal-engine.js`와 `trainer-adapters.js`가 담당한다. 학습 완료 후 `session-extras.js`가 영역별 저장소와 `competition.js`에 같은 회차 ID를 전달한다. 타이머, 점수/콤보, 오답, 단축키, 전체화면과 연습장은 기존 공통 흐름을 유지했다. 이전 경험치/배지 데이터도 변경하지 않았다.

이번 작업 전 이미 존재하던 수정/신규 파일을 보존했다. 이번 직접 수정은 `js/app.js`, `js/competition.js`, `css/style.css`, `css/platform.css`, `tests/competition.test.cjs`이며, 규칙·폰트·관련 검증 및 이 보고서를 추가했다. `index.html`, 계산·출제·정답 판정, 타이머와 저장 모듈은 이번에 수정하지 않았다.

## 랭킹 원인과 해결

운영 서버에 문서 이름만 요청하는 1건 제한 읽기 조회를 수행했을 때 분수 학급 컬렉션은 HTTP 200, 소수 학급 컬렉션은 HTTP 403이었다. 운영 데이터 쓰기는 수행하지 않았다.

사용자가 제공한 운영 규칙과 앱을 대조해 확인한 원인:

1. `decimalWeeklyCompetition*` 컬렉션이 읽기·쓰기 허용 대상에서 빠졌다.
2. 소수 개인 문서는 공통 계정으로 첫 학습을 완료할 때 점수와 함께 생성되지만, 기존 개인 생성 조건은 PIN을 가진 0점 등록만 허용했다.
3. 클라이언트가 기존 개인·학급 문서에 `trainerId` 등을 추가해 `onlyScoreFieldsChange()` 조건과 충돌했다. 분수의 기존 개인 문서에서도 발생할 수 있다.

수정된 앱은 기존 문서에 점수 관련 필드만 병합한다. 새 소수 개인 문서는 기존 공통 계정과 닉네임·학교·주간 ID를 비교하는 생성 규칙을 사용한다. 기존 계정·점수·영수증은 이동하거나 삭제하지 않는다. 기존 소수 계정의 PIN 검증과 회차별 중복 방지도 유지한다. 권한 거부 안내를 시간 초과 안내와 구분한다. 시간 초과는 서버 처리 여부가 불확실하므로 영수증에 기반한 기존 재시도 방식을 유지한다.

`firestore.rules`는 제공된 규칙을 기반으로 소수 경로와 생성 조건을 추가했다. 함수의 `let`을 지원하는 `rules_version = '2';`를 명시했다. 기존 점수 상한과 점수 필드 변경 제한, 삭제 금지, 영수증 목록/수정 금지, 예전 랭킹 읽기 전용은 유지했다. 기존 클라이언트 PIN 방식을 새 서버 인증 방식으로 바꾸는 작업은 포함하지 않았다.

## 운영 적용 — 아직 미게시

현재 환경에는 Firebase 관리자 인증/배포 연결이 없어 운영 규칙은 게시하지 않았다.

1. Firebase 콘솔의 `bunsutrainer` 프로젝트 → Firestore Database → 규칙에서 현재 규칙을 보관한다.
2. 프로젝트 루트의 `firestore.rules` 전체 내용으로 규칙 편집기를 교체하고 **게시**한다.
3. 수정된 웹 파일과 새 `fonts/` 폴더를 기존 정적 호스팅에 함께 반영한다. 빌드 도구나 신규 프레임워크는 필요 없다.
4. 소수 랭킹을 다시 열고, 같은 주간·같은 닉네임으로 학습 기록의 **반영 다시 시도**를 실행한다. 같은 회차는 한 번만 합산된다. 이전 주 기록의 재반영 제한은 기존 정책 그대로다.

운영 권한 적용 후 실제 랭킹 조회·반영 성공 여부는 별도 확인이 필요하다. 규칙 파일 추가만으로 운영 서버 설정이 변경되지는 않는다.

## 화면과 데이터

- 소수 10×10 모형의 행·열을 같은 크기로 고정해 색칠 칸과 빈칸의 면적을 일치시켰다. 교사 힌트/정답 표시로 축소될 때도 유지한다.
- 로그인 아이디와 학교/학반을 왼쪽에 묶고 조작 버튼을 분리했다.
- 준비 중인 사칙연산/도형 카드만 제거했다.
- 제목에 강원교육튼튼, 본문에 강원교육모두 Light 웹폰트를 동봉했다. 수식·숫자 입력의 기존 폰트와 세로셈 monospace는 유지한다. 출처는 `fonts/README.md`에 기록했다.
- localStorage 키·구조 변경, 초기화, 기존 데이터 migration은 없다. 온라인 컬렉션 이름과 회차 영수증 ID도 그대로다.

## 검증 결과

- Node: 237개 통과 (`node --test tests/*.test.cjs`).
- 실제 Firestore 에뮬레이터: 24개 통과. 등록·공통 로그인, 양 영역 첫/두 번째 학습 반영, 같은 회차 중복 방지, 개인/학급 조회, 계정 메타데이터 보호, 점수 상한, 삭제/영수증 수정/목록 거부, 미등록 소수 계정 생성 거부, 예전 경로 쓰기 거부를 검증했다.
- 분수 기존 회귀: 동작 200개, 레이아웃 133개 통과.
- 경쟁 모드 회귀: 동작 115개, 레이아웃 28개 통과.
- 타이머/도구 확장 회귀: 동작 56개, 레이아웃 16개 통과.
- 플랫폼 공통 로그인·영역 전환·분리 저장: 31개 통과.
- 소수: 49유형 개인 입력, 49유형 FHD 힌트/정답/풀이, 4종 개인 화면 크기 통과.
- 추가 표시 검사: 104개 통과. 1920×1080, 1366×768, 768×1024, 360×800에서 모형의 모든 칸 크기와 정렬을 측정했다. 실제 폰트 로드와 수식 폰트 유지, FHD 스크롤 없음도 확인했다.
- 위 브라우저 검사에서 예기치 않은 콘솔 오류 없음. 테스트 데이터는 전용 브라우저 프로필과 로컬 가짜 DB/에뮬레이터에만 작성했다.
- `git diff --check` 통과. 작업 시작 시점의 파일 사본과 비교해 기존 사용자 변경을 보존하고 이번 요청에 해당하는 수정만 추가했음을 확인했다.

브라우저 테스트 실행 시 이 환경에서는 `PYTHONPATH=tests/artifacts/python-deps`를 사용한다. 새 검증은 `tests/display_fixes_scenarios.py`, `tests/firestore_rules_scenarios.py`이다. 에뮬레이터 검증은 제외 경로 `tests/artifacts/firestore-tools/`의 Firestore emulator 1.22.0 JAR, Java 21 JRE(`**/bin/java.exe`), Firebase 8.10.1의 `firebase-app.js`/`firebase-firestore.js`를 사용한다. 서비스 실행/배포에는 이 도구가 필요 없다.

참고: [Firebase 규칙 안내](https://firebase.google.com/docs/firestore/security/get-started), [강원교육 서체 공식 안내](https://www.gwe.go.kr/main/content.do?key=m2307211207715).
