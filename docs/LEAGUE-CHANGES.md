# 개인 리그와 비밀번호 안내 수정 (2026-09-28)

## 수정 전 분석 및 영향 범위

`index.html`은 기존 CSS·스크립트를 로드하고 `app.js`가 화면 전환과 문서 단위 이벤트를 담당합니다. 문제 생성은 `problem-generator.js`, 분수 연산·정답 판정은 `fraction.js`, 화면 수식은 `ui.js`, 기록은 `storage.js`에서 처리합니다. `session-extras.js`는 점수·타이머와 결과 저장을 연결합니다. 전자칠판의 큰 수식·버튼·전체화면·단축키와 연습장도 이 흐름에 연결되어 있습니다.

이번 요청의 대상은 `competition.js`의 주간 순위 조회와 `competition-ui.js`의 입장·랭킹 화면입니다. 실시간 랭킹은 Firestore이며 기존 데모 랭킹은 별도로 유지됩니다. 개인·학급 모두 상위 50개만 조회하던 상태에서, 브론즈 참가자 전체의 정확한 순위를 표시하려면 개인 조회의 제한을 해제해야 했습니다.

## 수정한 기능과 구현 방식

| 전체 개인 순위 | 리그 | 리그 내 순위 | 상위 3명 표시 |
|---|---|---|---|
| 1~5위 | 다이아몬드 | 1~5위 | 금·은·동 트로피 |
| 6~10위 | 골드 | 1~5위 | 금·은·동메달 |
| 11~15위 | 실버 | 1~5위 | 금·은·동메달 |
| 16위부터 | 브론즈 | 1위부터 | 금·은·동메달 |

- 개인은 주간 전체 참가자를 조회하고 기존 점수 내림차순·동점 식별자 순서를 그대로 적용한 뒤 리그로 나눕니다. 점수가 변하면 리그와 리그 내 순위를 다시 표시합니다. 학급 상위 50개 조회와 메달은 유지합니다.
- 이번 주와 지난주는 각 주의 누적 점수로 독립적으로 리그를 나눕니다. 기존 월요일 오전 8시 전환·지난주 결과 표시 기간·주간 문서 보존 방식은 그대로입니다. 리그 정보를 서버에 중복 저장하지 않습니다.
- 빈 리그에는 참가자가 없다는 안내를 표시하며 임의의 참가자·점수·순위를 만들지 않습니다. 네트워크 오류와 구독 정리는 기존 흐름을 유지합니다.
- 다이아몬드 트로피는 금·은·동 색상과 순위 숫자가 있는 SVG입니다. 다른 리그는 기존 메달을 재사용하며 순위 이름을 접근성 레이블에 포함합니다.
- 화면의 PIN 문구·입력 예시·입력 오류·재입장 안내를 쉬운 **비밀번호 (숫자 6자리)** 표현으로 변경했습니다. 내부 변수·저장 필드·인증 방식은 유지합니다.
- 기존 새 닉네임 발급 버튼을 입장 카드 상단의 강조 영역으로 옮겼습니다. 최초 클릭은 확인 안내만 열며, 안내 체크와 별도 확인 버튼을 모두 거쳐야 실행됩니다. 연속 클릭은 즉시 초기화를 일으키지 않습니다. 취소하면 닉네임·비밀번호 입력과 기존 후보가 유지됩니다. 반 변경·주간 전환·화면 이동 시 이전 확인 상태를 폐기합니다.
- 초기화는 기존 `startNewDraft`로 새 닉네임 발급을 준비하는 기능입니다. 기존 비밀번호 변경이나 서버 계정 삭제가 아니며, 기존 점수와 학습 기록은 남습니다. 새 닉네임으로 점수가 이전되지 않음을 확인 전에 안내합니다.

## 기존 기능·데이터 구조 영향

`index.html`, `app.js`, 수학·출제·점수 계산·타이머·저장 모듈·연습장·기존 랭킹 모듈은 수정하지 않았습니다. 새 이벤트 리스너·타이머·라이브러리·빌드 도구도 추가하지 않았습니다.

localStorage 키·스키마·서버 컬렉션·기존 비밀번호 검증값·누적 점수는 변경하지 않습니다. 사용자가 확인 절차를 마친 경우에만 기존 새 닉네임 발급 방식으로 해당 주·학급의 후보 상태를 갱신합니다.

개인 랭킹 조회는 이제 전체 참가자를 읽으므로 참가자 수에 따라 읽기량과 화면 행 수가 늘어납니다. 실서비스 보안 규칙이나 배포 설정은 변경하지 않았습니다.
